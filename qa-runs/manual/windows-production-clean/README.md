# Windows Production Clean Run

This folder contains evidence from a clean Windows VM production run of NordSec Identity & Privilege Control Auditor.

## Test purpose

The purpose of this test was to verify Windows production collection on a clean Windows VM with a local administrator baseline and an intentionally added unauthorized administrator account.

## Test environment

Computer name:

WIN11-01

The test was run from PowerShell as Administrator.

## Baseline setup

The approved Windows administrators baseline included:

- Omidlab
- Administrator

The local Administrators group contained:

- Administrator
- Omidlab
- eviladmin

The user eviladmin was intentionally added to the local Administrators group but was not added to the approved baseline. The purpose was to verify detection of an unapproved Windows administrator.

## Command used

python app.py --mode windows --windows-log-hours 24 --windows-max-events 1000 --no-manual-cross-evidence

## Actual result summary

The application completed safely and generated reports, but the Windows collector did not complete all expected outputs.

The run produced:

- Windows identity data: collected
- Windows events: not collected
- Windows policy: not collected
- Fallback used: Yes
- Total findings: 1
- Critical findings: 0
- High findings: 0
- Medium findings: 1
- Low findings: 0

The generated finding was a partial Windows evidence finding.

## Important QA finding

This run exposed a Windows collector limitation.

The Windows audit log showed that the local Administrators group could not be read:

The local Administrators group could not be read. An unspecified error occurred: error code = 1789

Because of this, windows_identity.csv marked all users as IsLocalAdmin=False, including eviladmin and Omidlab.

This means the intended unapproved administrator finding for eviladmin was not triggered in this run.

Expected behavior:

If Get-LocalGroupMember fails, the Windows collector should fall back to another method such as net localgroup Administrators so local administrator membership can still be detected.

## Secondary QA finding

The Windows audit log reported:

Windows policy collection completed: 5 row(s)

However, windows_policy.csv was not created in data/collected/.

Expected behavior:

If policy rows are collected, windows_policy.csv should be written. If the file cannot be written, the collector should report the exact reason.
